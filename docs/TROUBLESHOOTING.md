# 问题、解决与脱敏案例

下面整理实际迁移中遇到的问题。项目名称、会话标题、私人路径、真实 IP、机器名、截图、令牌和日志均已删除；用“源端”“接收端”描述过程。此文不是原始聊天转储。表中的公开错误与步骤已按通用工具整理，不能把原现场方法验收当成所有版本通用工具已验收。

| 现象或错误 | 原因/判断 | 处理与验证 |
|---|---|---|
| 会话可见，但图片打不开 | 图片引用指向旧机器或已消失的临时上传目录 | 扫描用户图片引用，先复制原图，缺失时恢复传送字节；修正结构化路径并核对 SHA，重启后检查实际显示 |
| 只复制 `sessions` 后侧栏缺会话 | 桌面目录、会话数据库、项目归属没有同步 | 先注册接收端项目，预演选择性数据库导入与 local catalog 补充，不覆盖整个桌面状态 |
| `Unsupported schema migration difference` | 两端应用或内部数据库迁移链不同 | 检查 `_sqlx_migrations`，优先对齐应用版本；仅允许已实现的 root-turn 受限兼容，其他差异停止 |
| `A nontrivial root-turn relation cannot be omitted` | 源端 root turn 指向另一 turn，丢字段会改变关系 | 不做降级，先对齐版本后重新导出/预演 |
| JSONL 行序未变但投影不对 | 修改图片路径改变了 UTF-8 字节偏移 | 从真实日志行边界重算 turn 和 projection 偏移，保留正文摘要 |
| `Cannot identify a unique history anchor log` | history 偏移可能仍指旧续写日志，或存在多个候选 | 对同 UUID 的全部日志检查边界，只接受唯一锚点；不随便把所有偏移改为零 |
| 新窗口随 Codex 一起关闭/没有保持运行 | 子进程可能仍受宿主 Job 管理；新控制台或 detached 标志不保证脱离 | 通过 Win+R/开始菜单手动开独立 PowerShell，先运行脚本，再退出 Codex、按回车；检查成功结果文件 |
| 显示窗口/创建进程调用返回成功 | 只能证明创建调用成功，不能证明独立性或后续导入成功 | 查看实际进程、结束时间和最终文件；不要用 CreateProcess 标志或 `still_in_job` 单独判断所有退出行为 |
| `Completely quit Codex ...` | 桌面、托盘、CLI 或 app-server 仍运行 | 正常完全退出，等待进程结束；在独立终端重试，不一边聊天一边覆盖库 |
| `Recipient database/file changed since prepare` | 预演后目标继续产生写入，或同步包已变 | 暂停使用目标，重新 prepare；不要删掉 guard 来强制应用 |
| `Recipient local changes detected` / added or removed records | 接收端会话已分叉 | 先保留两边数据，人工决定合并或另存；不能当普通单向刷新覆盖 |
| `Existing chats require --baseline` | 缺少上次成功导出的基线 | 找到上次 `payload/export.sqlite`；没有可证明基线时停止，不能拿当前源库冒充基线 |
| `Mixed new/existing selections ...` | 既有首次导入又有更新 | 分两批处理 |
| `Add the target project ...` | 项目未注册、路径不同或重复 | 在目标 Codex 添加真实目录；重新 inventory 和 prepare，不复制源机器的全局项目 ID |
| `Some user images cannot be recovered` | 原图和发送内容都不存在，或日志不完整 | 查看私有图片审计；寻找原图/完整原日志，或明确接受缺失后另行设计，不生成假图让本工具通过 |
| `Ambiguous image variants` | 同路径多个传送版本 | 根据审计 SHA 选择正确版本，使用 `--image-choices`，保留选择理由 |
| `WinError 3`，文件和父目录看似都存在 | Windows 路径可能过长，尤其 SHA 图片名加临时后缀 | 使用短 staging/home 路径；本工具已缩短临时名，不以“文件一定不存在”解释所有此类错误 |
| 日志锚点查找出现 `StopIteration`，路径含 `EXAMPL~1` 之类短名称 | Windows 8.3 短路径与解析后的完整路径字符串不同 | 本工具先解析源日志真实位置，导出确认后的相对路径；导入据此定位，不再用未经解析的绝对字符串识别同一日志 |
| `python.exe` 无法启动 | Windows Store alias 或解释器不可访问 | 使用实际安装解释器完整路径；脚本 `-Python` 参数可指定 |
| SQLite 文件被锁/清理时报 `WinError 32` | 应用持有连接，或异常路径未释放连接 | 退出应用；本工具异常路径关闭数据库连接；不要清理运行中数据 |
| TCP 超时/HTTP 连不上 | 监听地址、接收 IP、网络配置或防火墙 profile 不匹配 | 先看监听，再从接收端测 TCP；规则限制端口、程序、接收 IP，结束后删除规则 |
| `403` | 接收 IP 或 Bearer token 不匹配 | 私下传最新连接文件，核对 peer；不可扩大到所有来源来绕过 |
| SHA/CRC 不一致 | 传输截断、旧 ZIP、文件变化或包不一致 | 拒绝应用，重新导出/传输；不改 manifest 来掩盖差异 |
| CLI 说登录/联网失败，但另一环境可请求 | 可能是网络沙箱、代理或权限，不必然是 token 过期 | 对照同一认证的只读请求和准确错误，区分网络限制与账户认证；不为了排障输出凭证 |
| WebSocket 重试后 `os error 10060` | 属于连接超时，需要单独查网络与代理生命周期 | 保存脱敏时间与错误，检查连接；不把它等同于迁移数据库损坏 |
| `Live data changed after migration ...` | 回退会覆盖之后的新工作，包括 WAL 写入 | 停止回退，先保护后续数据，再人工调和 |
| 导入结果显示 applied/passed | 表示离线操作或数据核验，不证明桌面已重启并显示图片 | 另做界面验收；目标暂离线时保留 `RESTART_VERIFICATION_PENDING` 结论 |

## 案例一：从“聊天存在”补到“图片可恢复”

初次检查数据库与日志，聊天能迁移，但用户原来发送的图片路径遗漏。随后按用户消息建立图片引用表，恢复仍存在的原文件；临时源文件不存在时，从原日志的用户 `input_image` 恢复传送字节。修改本地图片字段后，继续检查原消息正文未变、文件 SHA 与偏移一致。最终需要接收端界面实际显示才能完成验收。

教训：文件存在、数据库行存在、链接存在和真实像素显示是不同证据。报告应分别说明。

## 案例二：会话刷新遇到数据库版本差异

两端 history 迁移版本一度不同。首次预演停止，而不是强改目标 schema。检查发现差异来自一个新增 root-turn 字段；只有 NULL 或自引用的记录才有保留意义的降级处理。之后目标应用自身升级，重新采集的版本一致，则按一致结构正常处理。不能根据第一次 inventory 继续假定目标始终是旧版本。

教训：准备阶段和应用阶段都要核验实际数据；表头相近不等于语义兼容。

## 案例三：独立窗口与最终确认

从工具创建窗口后，进程仍可能受宿主管理。创建返回值、控制台标志和实际退出行为没有完全一致，所以改用用户从系统入口手动打开终端，完全退出应用后继续。源端收到离线完成报告后关闭临时传输服务和防火墙规则；接收端仍未重连时，只确认离线数据操作，不提前确认重启界面。

教训：使用真正独立的执行入口，用最终结果文件核验执行状态，最后撤销传输能力。

## 案例四：备份不能自动当作垃圾

预演副本、源快照、ZIP 和回退备份都会占磁盘。回退备份可能是唯一恢复办法；上次导出库可能还是下一次刷新的基线。迁移后把文件按角色列给用户，显示大小、默认保留、允许逐项选择。用户确认数据和界面后才决定删除，不能自动把整个迁移目录连真实图片一起删掉。

## 报错时提供什么

提供命令名、Python/Codex 版本、两端 migration 版本、脱敏错误和预演状态。不要粘贴 inventory 全量输出、数据库、真实消息、图片审计路径、token 或原始配置。先看 [SECURITY.md](../SECURITY.md)。
