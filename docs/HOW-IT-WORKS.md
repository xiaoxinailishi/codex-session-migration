# 实现原理与保留边界 / How it works

## 数据不是只有 sessions 文件夹

在本项目所处理的本地布局中，会话涉及以下层次。它们是观察到的内部格式，不是稳定公开 API：

| 层次 | 作用 | 处理方式 |
|---|---|---|
| `state_5.sqlite` | 会话属性、项目、cwd、rollout 路径 | 选择 `threads` 及相关表，映射目标目录 |
| `thread_history_1.sqlite` | turn、消息 item、投影状态、日志偏移 | 选择四张会话表，核对结构后写入副本 |
| `sessions` / `archived_sessions` JSONL | 原始消息、发送图片、续写与投影依据 | 找到选定 UUID 的日志，保留完整行和行序 |
| `<home>/sqlite/codex-dev.db` | 桌面本地会话目录 | 仅更新选定 local-host 目录项 |
| `.codex-global-state.json` | 桌面项目注册、归属及 UI 状态 | 使用接收端项目注册，只补选定会话归属 |
| `session_index.jsonl` | 会话名称索引 | 更新选定条目，其他行原字节保留 |
| 原图片或发送内容中的 base64 | 用户图片实际内容 | 复制确切字节，SHA 命名后保存到长期目录 |

直接复制日志可能让会话不出现在侧栏，或让消息存在而图片路径仍指向旧机器。用源端整库覆盖目标又会覆盖目标已有内容。因此工具在接收端用 SQLite backup API 制作副本，按选定 UUID 写入，再验证其他行摘要未变。

## 导出与并发

源数据库以 `mode=ro` 打开，并在每个数据库内使用读事务。SQLite 备份 API 能读到已提交 WAL 内容；不要只复制正在写入的主数据库文件。独立数据库间不存在统一事务，所以工具会阻止活动 turn，并要求选定会话在迁移窗口内停止继续使用。

日志按捕获时的文件长度读取完整行，截去尚未完成的尾行。读取后的副本是之后修复的输入。历史表里的偏移必须落在副本的行边界；不能只按数据库当前记录的文件名推断锚点。

同一个 UUID 有时存在多个续写日志。优先选数据库当前 rollout 对应且偏移匹配的日志；若不匹配，只允许唯一一个匹配的旧日志作为投影锚点。找不到唯一锚点即停止。所有选定日志都会打包，只有锚点的偏移用于重算数据库字段。

## 图片恢复

1. 从 `userMessage` 中的结构化 `localImage` 路径收集引用。
2. 找用户 `response_item` 中 `<image path="...">` 与随后 `input_image` 的配对。
3. 原文件还在时采用原文件；否则从 data URI 解码实际传送的 PNG/JPEG/GIF/WebP 字节。
4. 同路径出现多个候选版本时停止，让用户按审计表的 SHA 明确选择。
5. 资产写入目标长期目录；改写结构化图片路径与单独的 image wrapper，保留正文文本摘要。

发送过程可能缩放原图。`transmitted_bitmap` 恢复的是传送版本，不可宣称找回了已消失的原图。SHA 检查证明字节一致；它不证明在 Codex 中已经实际渲染。不会生成替代图，也不把助手生成的项目产出当作用户上传附件。

## JSONL 字节偏移

改图片路径可能改变 UTF-8 字节数。工具保持记录行数与顺序，只序列化确有结构化图片路径变化的行；其余行原字节复制。对每个变化行累计字节差，并映射旧边界到新边界，修正 `rollout_byte_offset`、`rollout_end_byte_offset` 和 `next_rollout_byte_offset`。

这类偏移是字节位置，不是字符位置；含中文时用字符串长度计算会出错。工具检查每个引用点确实落在旧行边界，无法对齐时不猜测偏移。历史正文内出现的旧电脑路径会作为原始历史保留，不做全局字符串替换。

## 更新基线与 schema

首次导入只允许目标没有选定 UUID。更新只允许目标全部存在，且有上次成功导出的基线。比较选定消息主键、消息内容与 turn 状态；图片路径在不同电脑上可能不同，比较时将图片路径标准化。结构化行的实际 SHA 在应用前另外检查。

在已设保护上限内，数据库结构相同时按实际列导入。唯一已实现的版本差异是 history migration 8 到 7：新增 `root_turn_id` 为 NULL 或等于本 turn ID 时可省略，其他关系停止。不会伪造迁移版本或升级目标数据库。未来结构、反方向差异和不同迁移链停止，参见[兼容性](COMPATIBILITY.md)。基线导出库还保存图片 SHA，刷新时比较接收端真实图片字节；缺少图片基线摘要时停止，不只忽略路径差异。

## 离线应用、回退与验收

`prepare` 保存目标所有数据库表摘要和待替换文件 SHA。`apply` 再检查完全退出、独占访问、摘要与 SHA，再备份目标文件及 WAL/SHM。每个文件在同目录用短临时名写入并替换，避免增加 SHA 图片名的 Windows 路径长度。

多个目标文件之间没有跨文件系统事务。普通运行错误会触发逆序恢复；断电或强行结束进程需要检查备份和当前状态。不要把“每个文件原子替换”误写成“整个迁移天然原子”。

手动 rollback 除文件 SHA 外，还读取数据库所有表的摘要，包括 WAL 中已提交的新修改；如果有后续工作就停止。回退不是合并。`verify` 对选定数据库记录和图片等文件作严格比较；桌面 UI 的普通变化不能靠全局 JSON 字节 SHA 判断，界面验收需另外完成。

## 不包含的能力

不迁移登录凭证、项目源文件、私人配置或任意助手产出；不支持非图片 thread attachments、活动实时流、自动双向合并、未经预演的任意新数据库格式或后台常驻自动同步。工作目录权限只映射明确的项目/home 范围，旧机器未映射的绝对授权根不会直接带入。

OpenAI 的 [environment variables 文档](https://learn.chatgpt.com/docs/config-file/environment-variables)说明 `CODEX_HOME` 和 SQLite 目录变量。这里的内部表迁移逻辑来自社区实现，不把官方环境变量文档当成迁移兼容保证。
