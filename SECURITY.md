# Security and privacy

The repository contains only reusable source code, de-identified methods, and synthetic fixtures. **A package generated by the exporter is private data**: selected conversations may themselves contain credentials, proprietary code, personal information, tool outputs, and local paths. Excluding authentication files does not sanitize conversation text.

Do not publish `auth.json`, real `config.toml`, inventory output, connection/token files, native databases or WAL/SHM, JSONL rollouts, migration ZIPs, recovery audits, validation reports, screenshots, or real image files. The `.gitignore` is a convenience; an allowlisted publication and content review remain necessary.

Use private storage for migration stages and backups. Anyone able to alter the package, manifests or tool source can change its meaning; SHA-256 detects accidental corruption only when expected hashes come through a trusted channel. ZIP checks are not a substitute for trusting the sender. Run this tool as the owning user; do not import packages from unknown parties.

LAN transfer is optional plaintext HTTP with a single peer IP and short-lived Bearer token. It does not provide confidentiality against a hostile network. Use a trusted LAN or an encrypted channel. Close the service and remove temporary firewall rules after transfer. Tokens should be delivered privately to the intended recipient and never printed into public reports.

Applying and rolling back native databases requires fully quitting Codex. Keep backups. Ordinary publication errors trigger recovery, but forced termination or power loss can interrupt a multi-file operation. Preserve evidence and inspect state before retrying. Do not turn off guards to force an import.

Cleanup only deletes explicitly selected staging entries. Backups require an extra opt-in; live home, database and image roots are protected. Deleting backup data can remove the only available rollback path. A previous successful export may be needed as the next refresh baseline.

For bug reports, share software versions, migration version numbers, synthetic reproductions and redacted errors. Do not attach private stages. For a security vulnerability, use GitHub private vulnerability reporting if available; otherwise contact the repository owner privately through their public profile rather than posting an exploit with private data in an Issue.
